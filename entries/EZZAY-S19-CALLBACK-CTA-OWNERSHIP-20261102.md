# S19: callback contracts and single CTA ownership

## Failures retained
The recovered source initially used a two-argument cover wrapper although the core calls the five-argument drawing contract. The child failed before image output with `h.text is not a function`; the outer driver exit code alone did not establish success. The additive wrapper preserves all five arguments and deliberately suppresses cover text.

Actual sixteen-native review then found the magnifier leader crossing its heading and the custom CTA colliding with the core CTA. Moving only the leader endpoint cleared the heading. A first CTA guard based on `scene.suppress_text` failed: the core CTA dispatch reuses the last scene without that flag. Six new actual images preserved that failed attempt. The final v005 removes only the redundant custom CTA; the existing core remains its sole owner. Canonical script/audio and the mechanism state are unchanged.

## Retest
The final six original images were actually inspected before production. Full v005 encoding and QA passed 1,860 physical frame timestamps, decoded video checks and exact canonical lossless PCM. Delivery AAC identity and waveform checks were separate. Every direct child reported terminal zero and reaped. Two reviewers actually inspected all 1,860 chronological thumbnails and all 32 selected native witnesses. Leader/title, signal-to-chip/display progression and the single CTA were clear within that scope.

## Limits and reusable lesson
No actual normal-speed playback or audio listening was performed by these reviewers. This is a qualitative sensor schematic, not clinical or calibrated optical validation. Reactive child monitoring is not proven parent-loss containment. Historical failed/native-HOLD outputs remain immutable. Check the actual caller's argument and state contract, not a convenient assumed flag. Assign CTA ownership once and review the real CTA dispatch, including encoded output, rather than adding overlapping guards to independently drawn copies.
