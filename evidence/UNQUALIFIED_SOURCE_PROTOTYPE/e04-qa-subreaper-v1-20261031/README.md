# Subreaper executable SOURCE prototype — synthetic BAT only

This is additive to frozen architecture14015b9f… and does not modify any production, quota, QA or master runtime. There is no actual config/GO or live qualification. All source tests use fake process/FD objects under AS128MiB/CPU30s. No child, native syscall, socket, lease or registry operation was exercised.

## Chosen tradeoff
A direct-parent supervisor would own every decoder from birth but requires a remote Popen/wait proxy because the controller cannot waitpid its sibling. This prototype instead makes the outer process a Linux child subreaper. The capped controller retains its REAL subprocess.Popen and ordinary wait/poll/pipe semantics. Each decoder is a same-PID bootstrap→target exec; PDEATHSIG binds its creating controller thread. The controller bootstrap binds PDEATHSIG to the retained outer thread. If the controller dies before reaping, the continuously-live subreaper adopts the decoder and can reap it independently. The outer holds the shared lease throughout.

**Residual lost-report gap:** if controller successfully waitpid-reaps a decoder and dies before transmitting its REAPED packet, outer waitpid returns ECHILD. This prototype does not infer a code/reap from that result. It keeps the lease/HOLD indefinitely pending explicit disposition, rather than claiming every controller-death case reconciles. Therefore this prototype is NOT a guarantee of automatic recovery or a production-ready replacement. Outer/environment loss still leaves unresolved START; PDEATHSIG is kill intent, not observed reap. Numeric namespace/PID matches in a later runner never restore the in-memory ownership/pidfd capability.

## Source components
- `supervisor.py`: root-gated synthetic BAT CLI, PR_SET_CHILD_SUBREAPER/readback, exclusive lease, durable journal, actual controller Popen, pidfds, bounded credentialed ACKs, exact release, adopted-child rescue and retained-lease cleanup. Same still-live owner only; no resume-by-PID. Common configured synthetic registry denies every unresolved prior START.
- `bootstrap.py`: creating-parent PID/start/boot/namespace check before/after PDEATHSIG setup, actual role limits readback, regular lease identity, target no-privilege/capability check, held verified executable FD, bounded ACK+self-pidfd+private release channel, same-PID fd-exec. No credential changes permitted. Held FD closes pathname replacement race; in-place binary writers still must be excluded explicitly.
- `controller_adapter.py`: wraps only exact allowlisted decoder command Popen; returns the REAL object and preserves normal wait/poll. Owns it before fallible IPC/identity reads. Normal observed reaping reports include full registered identity/generation; duplicate identical reports are idempotent and conflicting reports reject. Bootstrap failures/IPC failures remain failures, not invented closure.
- `ipc.py`: SOCK_SEQPACKET messages<=4096 bytes, max2 passed descriptors, kernel sender credentials, truncation/EOF rejection. Media stdout/stderr pipes are not relayed through this control protocol and are not copied or transformed.
- `ownership.py`: injected cleanup loop isolates monitor/log/signal/sleep/fsync faults, checks every child and never releases lease until observed closure plus durable terminal. Newly adopted children discovered at terminal cause cleanup again.
- `bat_controller.py` / `bat_child.py`: synthetic byte-output/sleep fixtures only. Supervisor CLI rejects any other controller/child script target; no ffmpeg/media command is admitted by this source. These are NOT tests that were run here.

## Durable release protocol
Before spawn: root source/config grant, fresh source hashes, resource inheritance check, subreaper setup, exact shared lease and empty unresolved registry. START is exclusive+fsynced before Popen. Actual Popen is retained immediately, then pidfd/identity/journal. Bootstrap cannot exec target until outer checks kernel credentials, self-pidfd, parent identity, generation, target/command SHA, actual limits and lease; registration is fsynced before release. Controller readiness follows its own ACK. Video/audio are sequential, never duplicate roles. Controller exit0 is insufficient if any decoder remains alive. Outer rescue can inspect/adopt only its kernel-current direct children while this same outer process/lease/generation remains alive—never after host/tool restart.

Stop uses exact retained pidfd or still-original Popen handle if pidfd setup failed, not a numeric-PID guess. TERM is followed by KILL after5seconds; either signal is only a request. Reaping/journal failure preserves HOLD/lease; no bounded-reap promise. Main owner thread creates all children and remains retained; PDEATHSIG is a creating-thread property. No in-process worker-thread spawning is allowed.

## Explicit resource proposal (not granted)
Outer must not inherit an exhausted controller CPU budget and must not be unbounded. Its low SOFT limits are AS256MiB/DATA128MiB/CPU30s/FSIZE1MiB; HARD inheritance ceilings must allow existing child limits: AS2GiB/DATA512MiB/CPU240s/FSIZE24MiB, STACK8MiB/CORE0. A prior AS256hard/CPU60hard proposal is incompatible with raising unprivileged children to existing caps and is NOT used here. The prototype rejects incompatible child hard limits before spawn. Outer RSS128MiB is included inside the existing NEW aggregate2GiB envelope along with controller384MiB +one decoder256MiB. This nominal768MiB sum is not a reservation.6GiB prestart/4GiB running floors and1s observed cadence remain proposed; own warning/shutdown and exact numerics require new root grant. Controller softCPU210/hard240 is also a new disclosed proposal, not an adopted existing cap.

Original002 and005r3 remain UNKNOWN in the current environment. The prior single-old reserve cannot cover them both. This source gives NO coexistence, media restart or historical process-disposition authority. Synthetic execution can occur only in a separately certified BAT environment under `ROOT_APPROVED_ISOLATED_BAT_SYNTHETIC_LIFECYCLE_ONLY`, source/config hashes and explicit no-media/new-BAT/writer-exclusion flags. No config or GO is supplied here.

## Deployment source identity
The source freeze uses single-component relative member paths beneath this source directory, so exact verified source bytes can be materialized into a separately restored BAT without rewriting the source manifest. Runtime paths/hashes are NOT silently repinned: actual BAT config must carry a separately audited nonempty runtimePins closure including its exact Python, ctypes/libffi/loader and target dependencies, root-GO-bound config hash, current lease identity and registry. Old environment runtime/GO cannot authorize the new host. No actual configuration is generated here.

Both bootstrap Python AND eventual synthetic controller/child target argv explicitly require -I -B. Bootstrap flags do not survive exec implicitly. Target import environment and runtime closure must still be qualified in BAT; site is enabled intentionally.
